# Phase 0 Pose Landmarker実現可能性レポート

実施日: 2026-09-20

## 結論

ブラウザ方式は、今回のmacOS上のheadless Chromium、CPU delegate、MP4 17本では**条件付きで成立**した。製品候補はWeb Worker内のPose Landmarkerを固定10fpsで動かす方式とする。全提示フレーム処理は固定10fpsより約6.9倍長く、MVPの既定にはしない。

固定10fpsの同一条件2走では、17本すべてでフレーム数とtimestampが一致し、比較可能な268,488座標値の最大差は0、推論時間以外の全集約指標の差も0だった。これは同じブラウザ、端末、モデル、サンプル時刻に限った再現性であり、端末横断のbit一致を意味しない。

一方、撮影条件による欠損は無視できない。事前に固定した品質ゲートを通ったのは11/17本、固定10fpsと全提示フレームの両方で通ったのは9/17本だった。したがって、製品では低検出時に数値を表示せず、撮影し直しを案内し、LLM分析だけを続ける縮退動作が必要である。

成功7本・失敗10本の分布には差が見える指標もあったが、技、撮影角度、通常速・スローが交絡している。統計的有意性や成功判定精度は主張せず、履歴で同一利用者の変化を見る決定的な数値として扱う。

## 実行条件

| 項目 | 条件 |
| --- | --- |
| ランナー | Node.jsからPlaywright 1.63.0を起動 |
| ブラウザ | headless Chromium |
| 推論場所 | module Web Worker |
| ライブラリ | `@mediapipe/tasks-vision` 1.0.1 |
| モデル | `pose_landmarker_full` float16 v1 |
| モデルSHA-256 | `5134a3aad27a58b93da0088d431f366da362b44e3ccfbe3462b3827a839011b1` |
| delegate | CPU |
| 入力 | `eval/manifest.json`のMP4 17本（成功7、失敗10） |
| 固定方式 | 動画時刻から10fpsで選んだフレームを2走 |
| 比較方式 | `requestVideoFrameCallback()`で提示されたフレームを1走 |

全提示フレームはブラウザが提示したフレームであり、コンテナ内の全ソースフレームを必ず列挙する保証ではない。今回は3,297フレーム中、`presentedFrames`カウンタ上のgapが1フレームあった。

## 指標設計

Pose Landmarkerの正規化33点とworld座標から、次を計算した。

| 分類 | 指標 | 根拠と制約 |
| --- | --- | --- |
| 品質 | pose検出率、腰・膝・足首・つま先8点の下半身検出率 | 欠損が多い動画を群比較へ混ぜない |
| 膝 | 左右膝角度平均の最小値、p90-p10の伸展幅 | 踏み切りと着地での屈曲・伸展の代理 |
| 腰 | 腰中心のp90-p10上下幅を胴長で正規化 | 絶対身長やカメラ距離に依存しにくい跳躍量の代理 |
| 体幹 | 鉛直からの傾斜、着地後の傾斜幅 | 着地姿勢と崩れの代理 |
| 着地 | 膝角、左右膝差、足首高さ差、足幅、着地後の腰上下幅 | 片足着地やバランス崩れの候補。着地推定不能時はnull |
| 時間 | 腰上昇50%の往復時間、体幹角速度 | 撮影速度とサンプルレートに依存するため、動画間比較には注意 |

移動の頂点は画面上で腰中心が最も高い時刻、着地はその後に腰が上昇量50%の高さへ戻る最初の時刻という代理定義である。板の接地は見ていないため、実際の着地時刻とは限らない。板の検出、絶対跳躍高、医学的評価は対象外である。

- 33点poseを取得できたフレームが80%以上
- 腰・膝・足首・つま先のvisibilityとpresenceが0.5以上のフレームが80%以上

### 低検出と撮影条件

| 条件 | 本数 | ゲート通過 | pose平均 | 下半身平均 |
| --- | ---: | ---: | ---: | ---: |
| FRONT | 5 | 2 | 89.6% | 62.6% |
| REAR | 2 | 1 | 100.0% | 74.3% |
| SIDE | 10 | 8 | 88.4% | 85.6% |
| 移動 | 5 | 3 | 75.4% | 67.3% |
| 静止 | 12 | 8 | 96.2% | 81.8% |
| スロー | 5 | 4 | 91.3% | 91.3% |
| 通常速 | 12 | 7 | 89.6% | 71.7% |

この17本では、正面・背面よりSIDE、移動より静止、通常速よりスローで下半身検出率が高かった。ただし同じ動画を条件だけ変えた比較ではなく、技と人物も交絡している。スロー自体は低検出の共通原因ではない。検出フレーム内の人物ランドマーク高を画面比で確認すると、最も小さいollie-002（中央値12.9%）は判定可能だった一方、判定不能群は22.1〜68.2%にも分布したため、引きの画だけでも説明できなかった。

判定不能6本のうち、ollie-003、kickflip-005、ollie-009はpose自体が欠け、kickflip-008、ollie-004、ollie-006はposeは得られても下半身visibilityが不足した。撮影ガイドでは、全身と足先を画角内に保つ、できるだけSIDEから撮る、移動中も人物サイズと遮蔽を一定にする、可能ならスローを使う、と案内する。ただしSIDEやスローでも失敗例があるため、撮影ガイドだけでなく実測ゲートを必須にする。

## 成功・失敗の分布

次は品質ゲートを通った成功4本・失敗7本の固定10fps分布である。Cliff's deltaは成功値が失敗値より大きい組み合わせの割合から逆を引いた値で、検定結果ではない。

| 指標 | 成功中央値 | 失敗中央値 | Cliff's delta |
| --- | ---: | ---: | ---: |
| 膝角度の最小値 | 105.30° | 76.72° | 0.43 |
| 膝伸展幅 | 55.23° | 70.19° | -0.43 |
| 腰上下幅 / 胴長 | 1.121 | 0.607 | 0.36 |
| 着地体幹傾斜 | 9.08° | 7.01° | 0.56 |
| 着地後の腰上下幅 / 胴長 | 0.699 | 0.362 | 0.56 |
| 体幹角速度p95 | 25.55°/s | 10.49°/s | 0.57 |

膝角度の最小値、膝伸展幅、腰上下幅には分布差が見えた。判定可能なOLLIEだけに限っても成功3本対失敗3本で、膝最小角は106.21°対82.86°、膝伸展幅は50.46°対70.19°、腰上下幅は0.817対0.607だった。ただし各3本であり、因果や一般化はできない。

体幹系では、成功の着地傾斜と角速度が失敗より大きく、事前仮説と逆方向だった。KICKFLIP成功は判定可能1本だけで、技別比較が成立しない。したがって、体幹値を成功・失敗判定に使う根拠は得られていない。膝と腰も判定器にはせず、同じ利用者・技・撮影条件の履歴比較候補に留める。

## 処理時間

動画の合計時間は112.5秒、個別動画は4.1〜11.8秒だった。

| 方式 | フレーム | 処理時間 | 1本平均 | 備考 |
| --- | ---: | ---: | ---: | --- |
| 固定10fps 1走 | 1,118 | 59.4秒 | 3.49秒 | 最短1.93秒、最長6.72秒 |
| 全提示フレーム 1走 | 3,297 | 410.8秒 | 24.16秒 | 最短20.58秒、最長30.88秒 |
| 固定2走 + 全提示1走 + 初期化 | - | 534.4秒 | - | 約8.9分 |

平均推論時間は20.68ms/フレーム、初期化は平均96.9msだった。全提示フレームは固定10fpsの2.95倍のフレーム数だが、動画再生待ちを含む処理時間は6.92倍だった。スロー5本は固定10fpsで平均99.8フレーム・5.18秒、通常速12本は平均51.6フレーム・2.79秒で、スローは動画時間に応じて処理量が増えた。

## MVPへの提案と未確認事項

- 固定10fps、full float16 v1、CPU delegate、閾値0.5、モデルSHA-256を保存条件として固定する
- MVP表示候補は左右膝屈曲、腰上下幅、体幹傾斜に絞る。角速度、絶対跳躍高、板の状態は表示しない
- poseと下半身が各80%未満なら骨格数値を判定不能にし、撮影し直しを案内する
- 着地代理が得られない指標は0で埋めずnullにする
- Workerの進捗、キャンセル、タイムアウトを用意し、失敗しても動画アップロードとLLM分析は続ける
- 履歴比較では同じ技、撮影速度、サンプルレートの数値だけを比較する

T11-1で確認したのは1台のmacOS、headless Chromium、CPU、MP4だけである。その後T11-2で、S3に保存されていた実機`kickflip_10.mov`をPlaywright WebKit 26.6でデコードし、固定10fpsと全提示フレームの両方でWorker推論できることを確認した。詳細は[T11-2 骨格機能の設計](t11-2-pose-feature-design.md)に記録する。

Playwright WebKitはiPhone実機Safariの完全な代替ではない。iPhone Safari実機、Android、GPU delegate、20秒動画、低性能端末は引き続き未確認であり、製品組み込み後のリリースゲートとする。
