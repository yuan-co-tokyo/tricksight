# Pose Lab（T12-0・検証用ビューア）

製品に組み込むか、どの時系列特徴を評価に使うかを判断するための独立ページです。採点機能・Jev接続はありません。`app/`、`lib/pose/`、製品Worker、DBの変更は不要です。

## 起動

リポジトリのルートで、既存の依存がインストールされた状態から:

```sh
pnpm view:pose
```

`http://127.0.0.1:4174` をブラウザで開きます。ポート変更は `PORT=4175 pnpm view:pose`。終了は起動したターミナルでCtrl+C。

モデルキャッシュがなければ起動時に既存設定のGoogle公開URLからfullモデルを取得し、SHA-256を照合します。既存キャッシュがあれば外部通信なしで起動できます。ブラウザはモデル・WASMをこのローカルサーバから取得します。**選択動画と33点は端末内でのみ処理し、送信しません。** サーバはGETだけを受け付け、eval動画・診断JSONを配信するルートもありません。CSPでも外部接続を許可していません。

デスクトップChromeで閲覧・書き出しを確認済み。Playwright WebKitで解析・コマ送り・390px幅を確認していますが、iPhone Safari実機やSafariでの書き出しは未検証です。追加依存はありません。

## 操作

1. MP4 / MOV（3〜20秒、100MB以下）を選ぶ。製品と同じfull / CPU / 固定10fpsの解析が終わるまで待つ。
2. 「動画に入れるメモ」に技や自己申告の成功／失敗などを入力する。これは分析には渡さず、表示だけに使う。
3. 再生／一時停止、1×・0.5×・0.25×、シークバー、±0.1秒を使う。コマ送りは**ソース動画の全コマではなく10fpsサンプル単位**。
4. 「膝の最小フレーム」「推定頂点」「推定着地」で該当サンプルへ移動する。値がない場合は該当ボタンを無効にする。
5. 「数値入り動画を書き出す」を押し、このタブを前面に保つ。完了したら「動画を保存」を押す。録画途中に非表示へ移ると書き出しを中止する。
6. 必要なら「診断JSONを保存」。このファイルには**生33点が含まれる**。製品の保存APIには送らず、git管理外に保存する。

解析中止・動画選び直しではWorkerをterminateし、古い結果を破棄する。解析のツール側上限は180秒、Worker応答上限は60秒（製品の120秒設定を変更するものではない）。

## サンプルと表示の違い

`floor(duration × 10)`個の時刻 `0, 0.1, 0.2, …` 秒で解析します。全ソースフレームを推論に混ぜるとMediaPipe VIDEO追跡状態が変わるため、追加推論・骨格の補間は行いません。

- 指定サンプル時刻へのコマ送り: 「製品サンプル時刻」。
- 通常動画再生のサンプル間: **直前サンプルの骨格と数値を保持**し、接続線を破線にして「間の表示フレーム：直前の骨格を保持」と表示。
- 現在の表示時刻と骨格のサンプル時刻を両方表示する。サンプルにposeがない場合は、それ以前の骨格を引き継がず描画しない。
- `currentTime` seekはブラウザのデコードしたソースフレームを返すので、10fpsの指定時刻と元動画のpresentation timestampの完全一致を保証するものではない。
- 通常再生は `requestVideoFrameCallback` の提示時刻で描画。非対応時はRAF/currentTimeへ縮退する。

水色は `visibility >= 0.5` かつ `presence >= 0.5`、赤はどちらか不足。生33点全体を描くが、製品の下半身ゲートは腰・膝・足首・つま先の8点（23,24,25,26,27,28,31,32）。かかと29/30はこの8点に含まれない。左右はランドマーク上の人物の左右で、画面の左右とは限らない。poseと下半身のフレーム検出率がそれぞれ80%以上で品質ゲート通過。

## 値の定義と製品との差

サーバは `lib/pose/config.ts` / `metrics.ts` / `measurement.ts` / `browser-analysis.ts` を読み取り、メモリ上だけでtranspileします。非公開の `deriveFrame` 等を**検証サーバ上だけでexport**して再利用するため、式のコピーを持たず製品の定義と一致させています。製品ソース・export・Workerプロトコルは変更しません。生33点を返すのは `scripts/pose-viewer/worker.mjs` だけです。

| 表示 | 計算と単位 |
| --- | --- |
| 左右膝・平均膝角度 | 製品の `deriveFrame`。world座標があれば3D world、なければnormalized座標の腰→膝→足首角度。左右平均、degree。肩/腰のcoreと下半身8点の可視条件を満たさない場合は欠損 |
| 腰画面Y | 腰23/24のyの中点（画面の上0・下1）。製品の腰上下指標の入力そのもの |
| 腰相対高さ | `(全有効フレーム腰Yのp80 − 当該腰Y) / 全有効フレーム胴長中央値`。上向き正、胴長単位。フレーム間の差とp90−p10は製品の腰上下幅と同じ尺度。絶対跳躍高ではない |
| 体幹傾斜（候補） | 肩中点→腰中点のnormalized 2D座標、鉛直からの絶対角度（0〜90°）。製品の推定着地体幹中央値と同じ入力 |
| 左右膝差（候補） | `abs(左膝角度−右膝角度)`、degree |
| 足首高さ差（候補） | `abs(y27−y28) / 胴長中央値`、胴長単位 |
| 足幅（候補） | normalized 2Dの足首間距離 / 当該フレーム腰幅、腰幅単位 |

候補は動作との対応を目で確かめるためのもので、良し悪し・成功の閾値を持たない。2D値はnormalized x/yをそのまま使う製品の定義で、画角・投影・体の向き・アスペクト比に依存する。スロー動画の秒数は実動作時間ではない。値が欠損したら0に置き換えず「—」、グラフも線を切る。

右側には製品と同じ4集約値を表示する。**膝「最小値」は実装上p05**であり、単一フレームの最小ではない。最小フレームとp05を挟む2サンプル時刻を分けて表示する。腰上下幅は腰Yのp90−p10 / 胴長中央値。着地は腰上下動の50%交差による推定時刻で、板の接地を観測していない。

UNASSESSABLEの場合、`createPoseMeasurement`の製品結果は`metrics=null`のまま保持する。ビューアに限り計算途中の値を「診断参考・製品非表示」として表示する。これは採点・有効な比較値には使わない。

## 動画の書き出し

canvasに原動画・33点・低信頼度・欠損部位・サンプル時刻・フレーム数値6種・グラフ3種・品質判定を描き、`captureStream(30)` と `MediaRecorder` で録画します。

- 優先形式はWebM/VP9、次にWebM/VP8、最後にvideo/mp4。`isTypeSupported`で選び、未対応時は画面に案内する。
- 出力1280×1050、映像は縦横比を保って配置、録画1×、音声なし。解像度・codec・画質・尺は元動画の無損失コピーではない。
- 計算後の実時間録画なので、書き出しには元動画と同程度の時間がかかる。端末負荷によるコマ落ち、録画開始/終了の小さな時間差があり、厳密なフレーム正確性を保証しない。
- 膝/腰等の数値は同じ10fpsサンプル由来だが、書き出し先の再エンコードで増えた表示フレームに新しい推論結果はない。
- WebMのMediaRecorder出力はプレーヤーによってduration/seekメタデータの扱いが異なる。まずChrome等で再生する。QuickTime互換MP4を確実に作るには別途mux/encode経路の検討が必要。
- 背景化すると録画が止まるため、途中のファイルを完成品として渡さない。音声や編集可能な独立骨格トラックは書き出さない。

## 再検証と生成物

サーバ起動中に:

```sh
node --import tsx scripts/pose-viewer/verify.ts
```

既存`eval/manifest.json`・入力6本・Playwrightブラウザが必要。自己申告メタデータはmanifestから取得し、6本の解析・操作・録画を行う。記録済み動画だけの再生確認は `--exports-only`、録画中止と選び直しの操作確認だけなら `--controls-only` を指定する。

生成物はgitignore対象の `eval/output/pose-viewer/`。`report.json`、6本の`.webm`、6本の診断JSON、画面の`viewer-screenshot.png`、各書き出し動画の`*-export-frame.png`、`export-validation.json`が入る。検証を再実行すると同名生成物を更新する。

選定理由・今回の欠損観察・製品化課題は [T12-0検証記録](../../docs/t12-0-pose-viewer.md) を参照。
